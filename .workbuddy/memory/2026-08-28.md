## 视差滚动版（用户选 B）

用户确认要做视差滚动（选项 B），产出 `portfolio/parallax/parallax-scroll.html`。

**核心实现（可复用套路）**：
- 三层图 `position: fixed` 钉在屏幕上 + `.stage` 高度 250vh 制造滚动距离
- 每层给不同 `translateY(-scrollY * 速度系数)`：
  - 背景 0.02（几乎不动，最远）
  - 神像 0.10（中速）
  - 石柱 0.20（最快，最近）→ 近快远慢 = 视差纵深
- **防露边关键**：图层放大到 160% 高 + `top:-30%`，上下各留 30% 余量，translateY 移动时才不会露边（否则固定层一移就露白）
- 用 `will-change: transform` + `passive: true` 的 scroll 监听保证顺滑

**教学点**：在滚动路径放了 3 段说明文字（背景/神像/石柱各一段），滚到哪层讲解哪层，符合"带着做"的带教定位。

**给小白讲视差的口径**（这次没用上，下次可讲）：
- "近的快、远的慢" = 火车上看窗外：近处电线杆刷一下过去，远处的山半天不动
- z-index = 谁挡谁（前后顺序）；translateY 速度 = 谁近谁远（纵深）

## 推镜头版（用户澄清需求）

用户反馈："我不想往下滚啊，我是想滚了然后石柱放大、神像越来越接近"。
→ **需求本质**：不是位移视差（translateY），而是"滚轮当油门、画面往前推"的缩放推进（scale zoom）。

**改法**：把每层 `translateY(-scrollY * 速度)` 换成 `scale(from + (to-from) * p)`：
- 背景 1.0 → 1.06（几乎不动）
- 神像 1.0 → 1.35（越来越近）
- 石柱 1.0 → 1.70（放大最猛，压到眼前）
- 滚动进度 `p = scrollY / (stage高度 - 视口高)`，范围 0~1

**关键认知**（可复用）：
- scale 放大是往外扩，**不会露边**，所以不需要像位移视差那样预留余量/放大图层
- 滚轮在这里只是"油门行程"（stage 250vh 提供可滚动距离），画面本身 fixed 不动，视觉上只有"推进"
- `transform-origin: center center` 让放大从画面中心往外，制造"迎面扑来"
- 三层放大倍数差 = 纵深差：远景几乎不变、近景猛放大，这就是"推镜头"的错觉来源

**可调参数**：`zoomRange` 里每层的 `to` 值。石柱想更猛就 >1.70。

1. **石柱"向中间合拢"**（不要 center 外扩，要两排柱子往中间挤）

**差点踩坑**：以为是黑底 → 实际是「带场景的石像」，黑的部分只是阴影。我用 `RGB<25` 当透明抠 → **只抠掉深色阴影**，前景雪山元素被保留 → 神像叠在雪山背景上**过渡自然，色调统一**。

**操作流程**：
1. `Image.open().mode` 看：黑底 RGB / 带场景也是 RGB（看不出区别，要靠像素值判断）
2. PIL floodfill/阈值抠图（25 是硬阈值，太大容易糊掉主体细节）
3. GaussianBlur(radius=1.2) 给 alpha 做轻微羽化，避免硬边
4. 升采样到 2752×1536（旧版神像用 `layer-angel-old.png` 备份）
5. 直接覆盖 layer-angel.png，HTML 自动跟随

**给小白讲「黑底 vs 带场景」的分辨法**：
- 看 [0,0] 和 [中心] 的 RGB：黑底图 [中心] RGB 显著高；带场景图 [中心] 也接近 0/低亮
- 看像素分布直方图：黑底是双峰（一个在 0、一个在主色），带场景是连续分布
- **处理方法不一样**：真黑底 → 阈值抠；带场景 → 必须人/AI 抠出主体

## 预览面板"滚不动"的坑（重要·可复用）

用户反馈 parallax-scroll.html "滚不了"——排查发现：**present_files 的预览面板会把"页面滚动"吃掉**，依赖 `window.scrollY` + 页面高度（`.stage height:250vh`）的滚动交互在预览里不生效（用户之前在真实浏览器看是好的，第一次在预览面板里滚就露馅）。

**解法**：滚动驱动改成 `wheel` 事件直接驱动，不依赖页面 scroll：
```js
window.addEventListener('wheel', e => {
  e.preventDefault();
  target = clamp(target + e.deltaY * 0.0008, 0, 1);
}, { passive: false });
```
- 关键：`html,body { overflow:hidden }` 让页面本身不滚，进度完全由 wheel 累加
- `passive:false` 才能 preventDefault（阻止面板默认滚动）
- 平滑：rAF 循环里 `progress += (target-progress)*0.12` 做缓动

**多驱动兜底**（预览环境可能只有部分事件能到 iframe）：
1. wheel 滚轮累加
2. mousedown+mousemove 按住拖（scrub 手感，mousedown 设 flag）
3. touchmove 触屏滑动（deltaY 累加）
4. 底部进度条 click/拖（getBoundingClientRect 算比例，最保底，一定能点）

**教训**：凡是要在 present_files 预览里演示的交互，优先用 wheel/mousemove/click 这些"直接事件"，别依赖页面滚动高度。

## 石柱"从中间切开"的 bug（transform-origin 设反）

用户反馈滚动时石柱从中间切开。排查：`clip-path` 裁成左右两半后，`transform-origin` 设反了。

**根因**：`transform-origin` 是相对**元素自身盒子**（全屏）算的，不是相对 clip 后的可见区。所以：
- `100% 50%` = 元素右边缘 = 屏幕右边缘（不是"靠中心"！）
- `0% 50%` = 元素左边缘 = 屏幕左边缘

**我之前写反了**：左半柱子 origin 设 `100%`（右边缘）→ 左柱以右边缘为轴向左外扩；右半 origin 设 `0%`（左边缘）→ 右柱以左边缘为轴向右外扩。两柱各自往外跑，中间缝越来越大 = "从中间切开"。

**正确写法**（要"往中间合拢"）：
```css
#layer-pillar-l { clip-path: inset(0 50% 0 0); transform-origin: 0% 50%; }   /* 左边缘为轴 → 向右挤 */
#layer-pillar-r { clip-path: inset(0 0 0 50%); transform-origin: 100% 50%; } /* 右边缘为轴 → 向左挤 */
```

**通用口诀（可复用）**：想让一张图的某部分"朝中心靠拢"，就把它的 transform-origin 设在**远离中心的那一侧**（外侧边缘）。因为 scale 是从 origin 往外涨，origin 在外侧、内容就往中心方向涨。想"往两侧分开"就反过来设在靠中心一侧。
