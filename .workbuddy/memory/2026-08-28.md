## 视差滚动版（用户选 B）

用户确认要做视差滚动（选项 B），产出 `portfolio/parallax/parallax-scroll.html`。

**核心实现（可复用套路）**：
- 三层图 `position: fixed` 钉在屏幕上 + `.stage` 高度 250vh 制造滚动距离
- 每层给不同 `translateY(-scrollY * 速度系数)`：
  - 背景 0.02（几乎不动，最远）
  - 神像 0.10（中速）
  - 石柱 0.20（最快，最近）→ 近快远慢 = 视差纵深
- **防露边关键**：图层放大到 160% 高 + `top:-30%`，上下各留 30% 余量，translateY 移动时才不会露边（否则固定层一移就露白）
- 用 `will-change: transform` + `passive: true` 的 scroll 监听保证顺滑

**教学点**：在滚动路径放了 3 段说明文字（背景/神像/石柱各一段），滚到哪层讲解哪层，符合"带着做"的带教定位。

**给小白讲视差的口径**（这次没用上，下次可讲）：
- "近的快、远的慢" = 火车上看窗外：近处电线杆刷一下过去，远处的山半天不动
- z-index = 谁挡谁（前后顺序）；translateY 速度 = 谁近谁远（纵深）

## 推镜头版（用户澄清需求）

用户反馈："我不想往下滚啊，我是想滚了然后石柱放大、神像越来越接近"。
→ **需求本质**：不是位移视差（translateY），而是"滚轮当油门、画面往前推"的缩放推进（scale zoom）。

**改法**：把每层 `translateY(-scrollY * 速度)` 换成 `scale(from + (to-from) * p)`：
- 背景 1.0 → 1.06（几乎不动）
- 神像 1.0 → 1.35（越来越近）
- 石柱 1.0 → 1.70（放大最猛，压到眼前）
- 滚动进度 `p = scrollY / (stage高度 - 视口高)`，范围 0~1

**关键认知**（可复用）：
- scale 放大是往外扩，**不会露边**，所以不需要像位移视差那样预留余量/放大图层
- 滚轮在这里只是"油门行程"（stage 250vh 提供可滚动距离），画面本身 fixed 不动，视觉上只有"推进"
- `transform-origin: center center` 让放大从画面中心往外，制造"迎面扑来"
- 三层放大倍数差 = 纵深差：远景几乎不变、近景猛放大，这就是"推镜头"的错觉来源

**可调参数**：`zoomRange` 里每层的 `to` 值。石柱想更猛就 >1.70。

## 预览面板"滚不动"的坑（重要·可复用）

用户反馈 parallax-scroll.html "滚不了"——排查发现：**present_files 的预览面板会把"页面滚动"吃掉**，依赖 `window.scrollY` + 页面高度（`.stage height:250vh`）的滚动交互在预览里不生效（用户之前在真实浏览器看是好的，第一次在预览面板里滚就露馅）。

**解法**：滚动驱动改成 `wheel` 事件直接驱动，不依赖页面 scroll：
```js
window.addEventListener('wheel', e => {
  e.preventDefault();
  target = clamp(target + e.deltaY * 0.0008, 0, 1);
}, { passive: false });
```
- 关键：`html,body { overflow:hidden }` 让页面本身不滚，进度完全由 wheel 累加
- `passive:false` 才能 preventDefault（阻止面板默认滚动）
- 平滑：rAF 循环里 `progress += (target-progress)*0.12` 做缓动

**多驱动兜底**（预览环境可能只有部分事件能到 iframe）：
1. wheel 滚轮累加
2. mousedown+mousemove 按住拖（scrub 手感，mousedown 设 flag）
3. touchmove 触屏滑动（deltaY 累加）
4. 底部进度条 click/拖（getBoundingClientRect 算比例，最保底，一定能点）

**教训**：凡是要在 present_files 预览里演示的交互，优先用 wheel/mousemove/click 这些"直接事件"，别依赖页面滚动高度。

## 石柱"从中间切开"的 bug（transform-origin 设反）

用户反馈滚动时石柱从中间切开。排查：`clip-path` 裁成左右两半后，`transform-origin` 设反了。

**根因**：`transform-origin` 是相对**元素自身盒子**（全屏）算的，不是相对 clip 后的可见区。所以：
- `100% 50%` = 元素右边缘 = 屏幕右边缘（不是"靠中心"！）
- `0% 50%` = 元素左边缘 = 屏幕左边缘

**我之前写反了**：左半柱子 origin 设 `100%`（右边缘）→ 左柱以右边缘为轴向左外扩；右半 origin 设 `0%`（左边缘）→ 右柱以左边缘为轴向右外扩。两柱各自往外跑，中间缝越来越大 = "从中间切开"。

**正确写法**（要"往中间合拢"）：
```css
#layer-pillar-l { clip-path: inset(0 50% 0 0); transform-origin: 0% 50%; }   /* 左边缘为轴 → 向右挤 */
#layer-pillar-r { clip-path: inset(0 0 0 50%); transform-origin: 100% 50%; } /* 右边缘为轴 → 向左挤 */
```

**通用口诀（可复用）**：想让一张图的某部分"朝中心靠拢"，就把它的 transform-origin 设在**远离中心的那一侧**（外侧边缘）。因为 scale 是从 origin 往外涨，origin 在外侧、内容就往中心方向涨。想"往两侧分开"就反过来设在靠中心一侧。

**关键技术发现（可复用）**：
- 神像图的"脸部"实际在 image 中央 0.40~0.50 范围（白色石雕的脸+脖子+肩膀是连体），不是边缘的 0.20

**用户接下来想做的方向**：「转场后放一个其他视频画面，再弹作品集」——也就是推镜贴脸 → 转场进视频 → 视频上浮作品集卡片。我的判断是**分两步走**：①先验收贴脸 ②再做转场。视频转场三件待定：①视频素材从哪来 ②触发方式（滚到底自动 vs 按钮）③声音（muted 自动放 vs 带声需点击）。

## 拉到只剩脸部（v8）

用户反馈「再大一点，比如只剩下脸部这种」——继续放大，让天使脸真正占满屏幕。

**改动**：

- 神像 transform：**移除 translateY(-p*20)**（之前上浮会让脸偏，钉稳 38% 位置不动）
- 神像 p>0.85 淡出：**移除**（之前为了让位卡片淡到 0.7，现在脸部一直占场；卡片 0.88 浮现时是覆盖在脸上方飘出，z-index 8 > 神像 2 不冲突）
- 石柱 p>0.85 淡出保留
- 阶段标签：「贴脸·作品集浮现」→「特写·天使脸占满·作品集浮现」

**静态预览 face-preview-v2.png**：用 PIL 模拟终态（p=1.0 合成），直接验证"是不是只剩脸部"。结果：脸（古典天使像）占满屏幕，翅膀/衣袖在两侧肩膀形成天然画框，脸在 38% 偏上 = 仰视感。

**待用户确认**：
- 脸在 38% 偏上 OK，还是想正中央（改 origin 50% 50%）
- 5.5 倍够不够，还是继续到 6.5/7.5

**贴脸倍数回调**：用户觉得 5.5 倍只剩脸太诡异，改回 3 倍（保留 translateY(-p*20) 上浮 + p>0.85 淡出到 0.7）。结论：**"只剩脸"这个方向用户不要，3 倍贴脸（脸放大但翅膀/身体还在画面内）是他要的度**。以后做推镜贴脸，默认 3 倍起步，别直接拉到器官级特写。

**复用经验**：做"放大到只剩某个部位"这种效果，唯一要算准的是**两件事**：
1. **origin 位置** = 部位在原图中的相对坐标（百分比）—— 不是绝对像素
2. **scale 倍数** ≈ 屏幕高度 ÷ 部位在原图中的高度

例：屏幕 1080，部位在原图占 200px，1080/200 ≈ 5.4 倍 = 5.5 倍正好。这是反推的简单公式。

**✅ 用户确认「可以了」**：贴脸放大（scale 5.5 + origin 50% 38% 只剩天使脸）验收通过。下一步进入转场阶段（贴脸 → 切另一段视频 → 视频上浮作品集卡片），三件待定：视频素材 / 触发方式 / 声音。

## 推镜分段化（v10·节奏拆分）

用户反馈：「推进有点快，石柱还没看清楚就消失，神像又推进太快，能不能分成两段」。核心诉求是**分段节奏**，不是整体变慢。

**改动（parallax-scroll.html）**：
- `zoomRange` 每层加 `start/end` 区间，全局进度 p 映射成局部进度 `t = clamp((p-start)/(end-start), 0, 1)`：
  - 背景：`start 0 → end 1`（全程微放大 1.0→1.10）
  - 石柱：`start 0 → end 0.55`（**前半段让开** 1.0→2.20，看清楚），淡出从 `p>0.50` 开始（先看清再消失）
  - 神像：`start 0.45 → end 1.0`（**前 45% 不动，后半段才推进** 1.0→3.0 贴脸）
- 神像上浮 dy 从 `-p*20` 改成 `-t*20`（跟随神像段，段内从 0 到 -20）
- 滚轮灵敏度 `0.0008→0.0005`、触屏 `0.0012→0.0010`（配合整体放慢一点点）
- 阶段标签改成两段式：`石柱·让开·神像露出` → `神像·迎面推进` → `贴脸·转场`

**核心经验（重要·可复用）**：做多图层 scrub 推镜，**别让所有层共用一条线性进度**（那会"石柱没看够就没了、神像一路冲"）。给每层错开区间（staging），各自有戏份，才有电影感节奏。这就是"分段"的本质：不是调快慢，是**错开每层变化的起止点**。

## 推镜节奏再调（v11·从"两幕割裂"改回"并行错峰"）

用户反馈：「石像只在后半段推进太奇怪了，跟着石柱一起推进吧，但可以先推进一段石柱、过了几秒石像开始推进」。

**上一版 v10 的问题**：把两层完全错开成"两幕"——石柱 0~55% 独自让开、神像 45% 之后才动。中间神像有一段"干等不动"的空白，用户觉得割裂。

**本次改法**（错峰，不是割裂）：
- 石柱 `start 0 → end 0.80`（先亮相，跟到 80% 才停住）
- 神像 `start 0.45 → 0.14`（**晚石柱一点点启动，之后两者并行推进到结尾**）
- 石柱淡出时机 `p>0.50 → p>0.80`（跟到 80% 才淡出，别神像没跟上就消失）
- 阶段标签：`石柱·先亮相`(0~14%) → `石柱让开·神像跟上`(14~80%) → `贴脸·石柱退场`(80~90%) → `贴脸·转场`(90%+)

**关键认知（重要·可复用）**：分段有两种做法，效果完全不同：
1. **割裂式**（v10，错开整个区间）：一层先演完、另一层才上台 → 中间有"干等"空白，像两幕戏，用户觉得奇怪
2. **错峰式**（v11，只错开启动点）：两层几乎同时跑，但一层的 `start` 比另一层晚一点 → 有"先后次序"但无"干等"，更像真实镜头运动（前景先动、主体跟上）

**用户要的是错峰式**。以后做多层推进，默认用"错开启动点"而不是"错开整段区间"，除非明确要求"这一幕演完再下一幕"。

## 推镜变速（v12·缓动曲线 easing）

用户反馈：「太晚了，还是有点怪，这种推进只能一种速度吗？不可以先 xx 速度再到加快到多少速度吗」。

**核心洞察（重要·可复用）**：之前的推进是**匀速（线性）**——局部进度 `t` 直接乘到放大倍数 `s = from + (to-from)*t`。不管怎么调启动点、错峰，匀速推进都有"机械、匀速前移"的怪感。**用户要的是变速（先慢后快），像踩油门加速逼近。**

**改法**：加一个缓动函数表，让 `t` 再过一条曲线：
```js
const EASING = {
  linear:    t => t,
  easeIn:    t => t * t * t,               // 立方：起步很缓，结尾猛加速（推镜头最常用）
  easeInQuad:t => t * t,
  easeOut:   t => 1 - Math.pow(1 - t, 3)   // 先快后慢
};
// apply 里：
const t = clamp((p - r.start)/(r.end - r.start), 0, 1);   // 错峰区间
const e = EASING[r.ease || 'linear'](t);                  // 变速
const s = r.from + (r.to - r.from) * e;                   // e 代替 t
```
- 神像/石柱都用 `easeIn`（立方，先慢后快），背景保持 linear
- 神像启动点 `0.14 → 0.06`（几乎和石柱同步，只晚一点点）

**给小白讲缓动曲线（下次可用）**：
- 匀速 = 走路；先慢后快 = 踩油门/下坡越跑越快
- `t*t*t` 立方比 `t*t` 平方更"狠"（起步更慢、结尾更猛），推镜头一般用立方才有"冲过来"的劲
- 想更猛就换更高次幂，想温和就用平方

**经验提炼（重要）**：scrub 推镜的"节奏感"来自三个旋钮，分开调：①**错峰**（各层 start/end 错开）②**变速**（ease 曲线）③**整体灵敏度**（滚轮系数）。用户连续三轮反馈的"怪"，本质是从①调到③都没解决的"匀速"问题，最后是②（缓动）根治。以后做推镜默认就要上 easeIn，别从线性起步。

## 推镜变速再修（v13·easeIn 换成 easeInOut）

用户反馈：「匀速变快那一段感觉有点不是很丝滑」。

**根因（重要·可复用）**：`easeIn = t³`（纯"先慢后快"）**结尾处斜率最大**（导数 3t²，t=1 时=3）。滚轮是匀速滚的（每格 deltaY 一样），但画面"开头几乎不动、结尾猛窜"，最后**猛冲撞到贴脸又急刹车**。这种"输入匀速、输出越滚越猛+急停"的落差，就是"不丝滑"的体感来源。**纯 easeIn 天生不丝滑，不是没调好。**

**改法**：换成**缓入缓出 S 曲线** `easeInOut = t<0.5 ? 4t³ : 1-(-2t+2)³/2`（神像、石柱都用），结尾斜率也归零，画面"慢→快→慢"平滑收住贴脸，没有急刹。另留了 `smoothstep = t²(3-2t)`（两端斜率都归零，最丝滑）备选。

**修正 v12 的认知**：v12 说"推镜头用 easeIn 才有冲劲"——**错**。easeIn 冲是冲，但"结尾猛冲+急刹"反而不丝滑。正确结论：**要"先慢后快"的加速感，又要丝滑，用 easeInOut（慢→快→慢）或 smoothstep，别用纯 easeIn**。easeIn 只在"就是要结尾那一下狠冲"时才用。

**给小白讲（下次可用）**：
- easeIn（纯先慢后快）= 一直踩油门，最后撞墙急刹 → 顿挫
- easeInOut（缓入缓出）= 起步踩油门、中段最快、结尾松油门滑停 → 丝滑
- 丝滑 = **两端都别突变**（起步别僵、结尾别急刹），中间怎么快都行

## 推镜变速三修（v14·easeInOut 换 smoothstep）

用户反馈：「后面神像冲的有点太快了，可以放慢一点、加长一点时间这样」。

**根因**：`easeInOut`（立方）虽是 S 曲线，但**中后段斜率仍偏陡**，滚到后半段神像 scale 还是涨得猛。用户要"后段放慢 + 拉长"。

**改法**：神像 `ease: 'easeInOut' → 'smoothstep'`（`t²(3-2t)`，两端斜率都归零，峰值速度只有 easeInOut 立方的一半）。效果 = 贴脸过程被"摊薄拉长"，后段从容不猛冲。石柱保持 easeInOut（用户没说石柱，且石柱 80% 就停、不影响后半段）。

**关于"加长时间"的认知（重要·可复用）**：scrub 推镜里"时间"= 滚动行程 = 进度区间。神像区间已 `start 0.06 → end 1.00` 拉满，**没法再拉长区间**，所以"加长时间"只能靠：①换更平缓曲线（smoothstep，本次做的，等效摊薄）②降全局滚轮灵敏度（滚更多格才到头，但会连带石柱变慢）。**以后用户说"某层冲太快/加长时间"，先查该层 end 是否已到头——到头了就先换平缓曲线，别硬拉区间。**

**缓动曲线"快慢"档位（可复用速查）**，从快到慢：
- easeIn（立方，纯先慢后快，结尾最猛）> easeInOut（立方 S，中后段偏陡）> smoothstep（S，最平缓）
- 用户要"放慢后段"就从 easeInOut 降 smoothstep，要"更冲"就升 easeIn

## 推镜启动点再调（v15·神像和石柱一起启动）
