## 【bug 修复】"一点进去就是最后一帧"（视频没播）

- 现象：视频不播，一打开就直接是最后一帧定格图。
- 根因：v6 的「兜底①」用 `loadedmetadata` 事件 + `if(cv.paused && cv.currentTime===0)` 判断 autoplay 是否被拦——但 loadedmetadata 在视频**还没开始播**时就触发，此时 paused=true 且 currentTime=0 恒成立 → 兜底**每次都误触发**，showStill() 直接盖最后一帧图 + revealHero，视频根本没机会播。
- 【教训·必记】不能靠 `loadedmetadata` 时的 `paused && currentTime===0` 判断"自动播放被拦截"，这条件在正常 autoplay 下也必然短暂成立。**正确判断拦截：用 `cv.play()` 返回的 Promise，`.catch(()=>{兜底})`——只有播放动作真的失败(被 reject)才兜底。**
- 修复：删掉 loadedmetadata 兜底，改 `const p=cv.play(); if(p && typeof p.catch==='function') p.catch(()=>{showStill();revealHero();})`；setTimeout 兜底从 6s 改 8s 且加 `if(!revealed)` 守卫。

- 【声音·可复用结论】用户问"加音频怎么办" → 纠正认知：视频自带 aac 音轨，不是"添加"是"解除静音"。浏览器规则：静音=广告牌可自动播，带声=要敲门必须用户点一下。实现「点击开始遮罩」：`startedRef` 控制 muted，**关键坑**：出声的 play() 必须在 onClick 同一调用栈里同步 unmute+play 才被浏览器放行，不能靠 setState→useEffect 异步触发（会被当自动播放拦截）。所以 handleStart 里直接 `v.muted=false; v.play()`，effect 只依赖 [current] 不依赖 started，靠 ref 读状态。
