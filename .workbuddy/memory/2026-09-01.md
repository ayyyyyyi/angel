# 2026-09-01 ·换装游戏·图层对齐问题

## 问题：运营服（outfit-5）叠图时相对底模"往右偏"
- 用户反馈："感觉他们俩有点没对上，新的有点往右了"
- 不是"两个角色"问题（用户澄清），是水平位置偏移

## 诊断（PIL alpha 分析）
- 两张图都是 `object-fit: contain` + 绝对定位叠在 493×751 容器里，理论上居中
- 但角色在各自画布内的**位置不对称**：
  - BASE 底模（547×1471）：头部中轴在画布内 x=243.5，画布中心 273.5 → 偏左 30px
  - OUTFIT5 运营服（477×1485）：头部中轴 x=237.8，画布中心 238.5 → 基本居中
- contain 渲染后：运营服头部比底模**偏右 +15.0px**，全身中轴偏右 +11.5px
- 垂直方向已对齐（都 contain 撑满 751 高，脚底/头顶都贴容器边）

## 根因
- AI 生图（nano banana 局部重绘）时角色在画面里的位置不固定，有的偏左有的偏右
- 两张图各自 bbox 裁剪后都"居中"，但**角色视觉中轴 ≠ 画布中心**（发饰/姿势不对称）

## 解决方案（通用化，可复用给 outfit-1~4）
- CSS：`.character-img` 加 `transform: translateX(var(--dx, 0px))` —— 每张图可独立微调，默认 0 不影响 base
- HTML：outfit-5 加 `style="--dx:-15px"`（往左移 15px 对齐头部）
- **对齐方法（可复用）**：用 alpha 加权中轴算每张图的"身体中轴"，对比 contain 渲染后的中轴位置，差值就是 --dx 偏移量

## 待办
- 用户确认 -15px 是否对味，可能微调
- 后续 outfit-1~4 接入时，每张都要跑一次"中轴偏移"算 --dx

## 2026-09-01 ·创作服"矮胖"问题 → 加 scale 缩放开关

### 用户反馈
- "感觉创作他整体的人物有点矮？"

### 诊断（不是错位，是身材比例不同）
- 测了所有服装的「头部宽占身高比」和「裙摆宽占身高比」：
  - 底模/校园/实习/运营：头部宽都 23.2~23.5%，裙摆 18~37%
  - **创作服：头部宽 25.2%（大 10%），裙摆 48.9%（蓬一倍）**
- 根因：这张 AI 生图角色画得偏大偏胖，尤其洛丽塔大裙摆特别蓬
- contain 模式下高度都撑满容器，所以"矮"不是真矮，是"宽"带来的视觉错觉

### 解决方案（通用化）
- CSS `.character-img` 加 `scale(var(--scale, 1))` + `transform-origin: bottom center`
- 好处：以脚底为缩放基准，缩小后脚底仍贴地，头顶下缩
- outfit-4 设 `--scale:0.93`（头部 25.2%→23.4%，回归底模水平）
- 其他图不设 --scale，默认 1 不受影响
- dx 不变（scale 以 bottom center 对称缩小，水平中轴不动）

### 可复用经验（重要）
- **换装游戏对齐三要素：水平 dx + 垂直脚底贴地 + 头部大小一致**
- 之前只做了 dx（水平），漏了"头部大小"这一维——AI 生图每张角色画幅比例都不同
- 以后每接一套新服装，除了算 dx，还要测「头部宽/身高比」，跟底模 23.5% 对齐，偏差 >1.5% 就加 --scale 修正
- 测量脚本：alpha 逐段（0-20% 头部、60-80% 裙摆）取非零列宽
  - 头部宽度占身高比 ≈ 23.5%（底模基线）
  - 超出 ±2% 视觉就会"头不对"（创作服 25.2% 偏大、数据服 23.4% 几乎完美）

### 2026-09-01 ·scale 缩放基准踩坑（bottom origin → top origin）
- 用户反馈："更奇怪了 他们头都不在一个水平线上"
- 根因：scale 0.93 用了 `transform-origin: bottom center`（脚底为基准），缩小后**头顶下移 52px**，导致头错位
- 修复：改 `transform-origin: top center`（头顶为基准），头顶保持在 y=0，头对齐；代价是脚底上移 53px 悬空，被洛丽塔大裙摆盖住
- 【教训】缩放基准点决定了哪一端固定：bottom=脚贴地头顶掉，top=头顶贴顶脚悬空。换装游戏视觉焦点是脸，**应优先保证头顶/脸对齐，脚底悬空靠裙摆遮**
- 【待观察】脚悬空 53px 是否被用户接受，若接受不了 → 唯一彻底解法是重新生成头身比更接近底模的图（outfit-4 头身比 25.2% vs 底模 23.5%，图本身头大，CSS 无法同时满足"头大小一致+头对齐+脚贴地"三条件）

### 2026-09-01 ·最终回退：scale 方案整体放弃
- 用户反馈（第三条）："不是 感觉他的人物都小一圈啊" —— scale 缩小导致整体变小，用户不接受
- **回退**：去掉 --scale，CSS 恢复 `translateX(var(--dx))` 单轴，outfit-4 回到 `--dx:-8px`（dx-only）
- 【最终结论】outfit-4 与底模的身材差异（头大 7%、裙摆蓬 32%）是**图本身的头身比/风格问题**，不是贴图对齐问题。CSS 缩放无论如何都会顾此失彼：
  - 不缩 → 头大 7%、裙摆蓬（用户嫌"矮胖"）
  - 缩 → 整体小一圈（用户嫌"小"）
  - 缩+top origin → 脚悬空
- 【给用户的最终建议】要三全其美（头大小一致+头对齐+脚贴地），唯一解法是重新生成一张"头身比跟底模一致（头占身高 23.5%）、裙摆别太蓬"的图
- 【经验固化】换装游戏换装，同一角色的"身体比例"必须一致。以后接图前先量头身比，跟底模差 >1.5% 就直接让用户重生成，别指望 CSS scale 补

## 2026-09-01 ·视频背景「看不到」修复
- 【根因】base64 内嵌 1.5MB 视频在预览面板（iframe/WebView）解码失败——之前 index.html 封面视频能播，是因为那个视频小（~300KB base64 ≈ 200KB 原始）且单独使用。这次 1.5MB base64 + 切换时 play() + 预览环境 data URI 限制，三因素叠加就不行
- 【修复三件套】① src 从 `data:video/mp4;base64,...` 改成 `./bg-growth.mp4` 外部文件（浏览器 HTTP 流式加载，绕过 data URI 大小限制）② 加 `poster="./frame_0.jpg"` 兜底（视频未解码完/加载失败时显示首帧，不会黑屏）③ z-index 1 → 2 提到暗化层之上（彻底排除遮挡疑虑）

【重要经验·可复用·已纠正】上面"present_files 一起 present 视频"是**错的**——实测：present_files 把 HTML serve 到 `static-html/<hash>/` 目录，但列出的 mp4/poster **不会被放进该目录**，curl 验证 `bg-campus.mp4` 仍 404。所以 HTML 里 `./bg-campus.mp4` 相对路径永远加载不到视频。

✅ **正确做法：起本地静态服务器 serve 整个 dressup 目录，再 present localhost URL。**
- 命令：`python -m http.server 8766 --directory "C:/Users/ayiqianwang/WorkBuddy/vibe coding/portfolio/dressup"`（后台跑）
- ⚠️ `--directory` 在 Windows 上必须用 Windows 路径 `C:/...`，不能用 Git Bash 的 `/c/...`（MSYS 路径 Python 不认，会 404）
- 然后 `present_files("http://127.0.0.1:8766/dressup-demo.html", cwd=...)`
- 验证视频可达：`curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8766/bg-campus.mp4` → 200 才对

【通用结论】凡是"HTML 里用相对路径引外部资源（视频/图片/音频）"的页面，预览一律走本地 server + present localhost URL，不要指望 present_files 列文件能解决相对路径。base64 内嵌只适合单个小资源。
