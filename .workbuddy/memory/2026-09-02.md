## 关键经验·可复用
- **「延伸阅读 / 子模块」模式的两种实现**：
  - 整行横跨（grid-column: 1/-1）：视觉重、占满宽，但会把 N 列之后所有内容挤到下行 → 适合 N 条内容数量=3、有大量配图说明的场景
  - 嵌到主卡内部（grid-row: span 2 + 子元素）：让 N 之后的卡片"自然挤到下一行"，主卡变两行高 → 适合"主卡 + 一段附加说明"调性
- 用户对"产品/作品集页面里的英文小副标题"普遍持删态度——除非作品调性真的需要（如英文公司名、音译品牌）。如果用，留着要克制；不再需要就果断删。
- 卡片"放大"这件事，不只改大小，要同时拉 padding + 字号 + 容器宽度，三件事联动才有效；只改一个会显得"挤"。

## CSS Grid auto-placement 坑：当子项里出现 `grid-column: 1 / -1` 横跨子项时，别靠 auto-placement
- **坑点**：当 grid 容器有 4 个子项（3 主卡 + 1 横跨 extension），DOM 顺序是 N°01 → N°02 → extension → N°03，仅靠 auto-placement 时，浏览器会试图把 extension 塞进当前行导致不能完整跨三列，最终位置错乱。visual 是 N°01 在行 1，但 N°02 神秘跳到下行（N°02 本应在行 1 col 2）。用户截图为证：「乱」。
- **解决**：用 CSS 显式锁定每类子项的 row：
  ```css
  .detail-grid > .detail-card { grid-row: 1; }   /* 三张主卡强制在第 1 行 */
  .detail-grid > .extension-card { grid-row: 2; grid-column: 1 / -1; }  /* extension 强制第 2 行+跨整行 */
  ```
  不依赖 auto-placement，所有位置 = 确定性结果。
- **可复用判断**：今后只要 grid 里有「主体卡片 + 跨界模块」混排，先想这三种方案：「整 grid 子项跨界」最易踩 auto-placement 错位；要么改成「嵌套布局」（外层 flex 分上下两段、内部各自独立），要么用 `grid-template-areas` 显式画；要么用上面 `grid-row:1/2` 双行锁定。nested layout 最稳。

## 校园赛照片升级「手动拖拽横向滚动」（v13）
- 需求：4 张校园赛现场照从「点箭头轮播」改成「手动拖拽 + 吸附」——鼠标按住左右拖、触屏滑，图片跟手，松手 snap 到最近一张。
- 实现（纯 Pointer Events，无库）：
  - `pointerdown` 记录 startX/curX，`track.style.transition='none'` 取消动画，`setPointerCapture` 保证移出元素仍能拖。
  - `pointermove` 实时 `translateX(curX + dx)`，两端加 0.3 阻尼回弹。
  - `pointerup` 判断 `|dx| > 0.25*宽` 就切一张，否则回弹；恢复 transition 做 snap 动画。
  - `touch-action: pan-y` 让触屏只保留纵向滚动、横向交给拖拽；`cursor: grab/grabbing` 提示可拖。
  - 关键冲突处理：拖拽松手会触发 click，用 `car.dataset.justDragged` 短标志（60ms）让点图开灯箱的分支跳过——`|dx|<6px` 视为点击、否则视为拖动。
- 保留：左右箭头、圆点、点图开灯箱都还在，作为拖拽之外的辅助。
- 推文长图同轮次改为「瘦窗口（160px 宽）+ 竖向滚动」：`.extension-preview` 加 `overflow-y:auto`、img 改 `height:auto` 完整显示、`::after` 从"点击看大图"改为 sticky 顶部"↓ 下滑查看全文"提示、细金色滚动条。
- 【可复用】Pointer Events + setPointerCapture + snap 是「图片手动横滑/拖拽轮播」的通用范式，任何作品集要"跟手滑动"都直接套这个；`justDragged` 短标志是拖拽 vs 点击的唯一可靠解耦手段。
- v14 自动轮播：用户要的是「图片自动轮播」而非手动拖。加 `startAutoPlay(car)`：`setInterval(每 3s 切下一张循环)`，`mouseenter/pause + mouseleave/play`（悬停暂停、移出继续）+ `pointerdown/pause`（触屏/拖动暂停）。`total<=1` 直接 return 不播。自动播 + 手动拖 + 箭头/圆点三者共存，互不打架（都只改 `dataset.cur` + `translateX`）。

## v21 修复「推文横条互相覆盖」bug
- **现象**：N°02 和 N°03 都有 extension 时，两条推文叠在同一行，王者赛推文被公益节推文盖住。
- **根因**：CSS 里 `.detail-grid > .extension-card { grid-row: 2 }` 把所有横条都写死在同一行（第 2 行），两个横条重叠。
- **修复**：CSS 只保留 `grid-column: 1 / -1`（横跨），去掉写死的 `grid-row: 2`；改由 JS 在 renderCampus 里用计数器 `extensionCounter` 动态分配 `ext.style.gridRow = 2 + extensionCounter++`——第 1 条推文第 2 行、第 2 条第 3 行，依此类推。
- **可复用经验（重要）**：grid 里若出现**多个**「横跨整行的附属模块」，绝对不能用固定 grid-row，必须用计数器/`:nth-of-type` 之类动态分号，否则全叠一起。之前的 v12「grid-row:2 锁定」只适用于**单个** extension 的场景，现在升级成动态版。

  - 描述 13→14px + line-height 1.85→1.75 + 颜色加深（紧凑但不挤）
- tag hover 反色高亮 + 上浮 1px（让次要信息也"活"起来）
- **教学要点**：用户说"让人点进来看一眼抓住"→ 排版的本质是**视觉层级**（标题/副标题/正文/标签四档分明），字号差至少 6-10px 才能拉开，加粗+短线更强化层级。13/12/11 这种"差不多大"是小白最常犯的错。

## v23 详情卡「分段 + 高度齐平 + 横条同款化」三个改动
- **三个用户反馈一次到位**：
  1. 「给他分段一下呗」——三张卡描述段是 1 段连绵文字（"全程跟进... 短视频... 全域播放..."），视觉节奏太密。改成 3 段：每段左边一个**金色加粗小标签**（赛事内容/角色定位/视觉产出等）+ 右侧正文 + 1.5px 金色栏间线 + 行首◆金点。
  2. 「中间那个高度为什么和其他卡片不一样」——`.detail-grid` 当前 `align-items: start`（各自顶对齐），描述短的就矮。改成 `stretch`，最高那张撑满另两张，三卡齐平。
  3. 「下面推文的卡片也要改」——extension 横条 title 跟主卡对齐到几乎同尺寸（30px 衬线 + 金线）。
- **数据层升级**：`desc` 从 string 升级为 `array<{kicker, body}>`。向后兼容（render 时 `Array.isArray(item.desc) ? ... : [{kicker:'详情', body: desc}]`），未来新加卡可直接用 string。
- **CSS 新增**：`.desc-block`（flex 两栏）、`.desc-kicker`（min-width 60px 金色加粗 + 右边线）、`.desc-body`（15px + 行高 1.75 + KPI `<b>` 用衬线金色加粗）。
- **教学要点**：栏间 1.5px 金色竖线是「财经杂志」和「时尚杂志」的标配排版语言——让密集的内容在视觉上变成"章-节"结构，避免大段文字让人放弃阅读。


## v24 游戏经历「改成校园推文同款卡片」——单屏点击进 panel 而非 modal
- **用户诉求**：游戏经历点进去想做"像校园推文这样的卡片"——本质是 N°02 extension 那种【左文 + 右长截图】横排样式，省得裁图。
- **现在改了什么**：
  1. **HTML**：复制 `campusPanel` 结构，在它后面插入 `#gamingPanel`（标题"游 戏 经 历"）。
  2. **JS 数据**：`GAMING` 数组 3 条占位，每条字段 `{num, kicker, title, desc, image, tags}`。image 默认 `gaming1/2/3.jpg`。
  3. **JS 函数**：加 `renderGaming / openGaming / closeGaming`，照搬 `renderCampus` / `openCampus` 结构但去掉 carousel（直接复用 extension-card）。
  4. **路由**：`.card` 点击 `id === 5` 走 `openGaming()`（之前走 `openModal`）。ESC 同时关 campus/gaming。
  5. **CSS**：`.gaming-list` 用 flex column 堆叠 extension-card + gap:26px；`.gaming-list > .extension-card` 把 grid-template-columns 调成 `1.1fr 260px`（右侧更宽，给长截图空间）。
  6. **缺图兜底**：每个 `<img>` 监听 `error` 事件，触发后替换右侧为深色渐变 + "📷 缺一张截图 / 文件名 / 把你的截图丢到 dressup/gaming1.jpg" 的占位提示，点击不弹灯箱（避免空操作）。
- **教学要点**：
  - **"extension 卡片被复用"**这个套路值得记：校园推文 N°02/03 用的 `extension-card` 块样式（flex 左右栏 + 右图为长截图带滚动），其实就是"作品集"的【标准卡片】样式——任何"左描述 / 右长截图"的内容（推文、笔记、截图、攻略）都可以套这个。
  - **缺图兜底的三种姿势**：
    - ❌ broken 图标硬显示（丑）
    - ❌ display:none（卡片瘪了）
    - ✅ onerror 注入 div 占位 + 提示文件路径（用户后续替换一目了然）
  - **改细节面板的检查清单**：① HTML 容器 → ② 数据数组 → ③ render 函数 → ④ open/close 函数 → ⑤ 路由改 id → ⑥ close button + 点遮罩 + ESC 三处全绑。少一步都有 bug。
